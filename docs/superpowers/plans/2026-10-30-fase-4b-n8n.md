# Phase 4b — n8n Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A custom n8n node in TypeScript that talks to the agent's HTTP API, importable flow templates (email → agent → sheet, WhatsApp → agent, approval link), and a `docker-compose.yml` that runs agent + n8n together.

**Architecture:** `integrations/n8n/node/` is a standalone npm package `n8n-nodes-agentes-ia` scaffolded from the official `@n8n/node-cli` 0.54 (`declarative/custom` template) — declarative routing only, no runtime dependencies. Its credential holds the agent's base URL and optional API key (`X-API-Key`) and is tested against `GET /health`. Flows in `integrations/n8n/flows/*.json` use that node. `Dockerfile` (agent) and `integrations/n8n/Dockerfile` (n8n image with the node baked in) are wired by `docker-compose.yml`.

**Tech Stack:** Node 24, TypeScript 5.9, `@n8n/node-cli` 0.54.6, `n8n-workflow` (peer), n8n 2.45 (local verification via `npx n8n`, image `n8nio/n8n:2.45.7`), Python image `python:3.12-slim` + uv.

**Spec:** `docs/superpowers/specs/2026-10-30-agentes-ia-empresas-design.md` (Phase 4b; Phase 4a API in `docs/superpowers/plans/2026-10-30-fase-4a-api-web-mcp.md`).

## Global Constraints

- All earlier constraints apply (author, trailer, English code, Spanish user-facing text, LF, `set -o pipefail`, `python -m uv`).
- Branch `fase-4b-n8n` from `main`.
- Owner's choice 2026-10-30: **no Docker on this PC**. Compose and images are validated in GitHub Actions (`docker compose config`, `docker compose build`); locally n8n runs with `npx n8n@2.45.7`.
- Anti-goal from the spec: the agent itself is never rebuilt as n8n drag-and-drop; flows only call the agent.
- WhatsApp is only a flow template the user wires up (no Meta API code).
- The node package passes `n8n-node lint` in strict mode (official community-node rules) and `n8n-node build`.
- Thread ids sent by flows must match `^[A-Za-z0-9_-]{1,64}$` (Phase 4a API rule).
- Assistant's calls: compose sets `AGENTES_API_KEY` from `.env` with no default — `docker compose up` fails fast with a clear message if it is missing; the agent container listens on `0.0.0.0` (allowed because a key is set); n8n data in a named volume.

## Review Focus

1. A sender address or phone with characters outside the thread pattern (`ana.perez+ventas@ejemplo.com`, `+57 300 123 4567`) → flows sanitise it to a valid thread id, never a 422 (Task 3 test).
2. The agent answers with a pending action instead of text → flows record/announce "pendiente de aprobación" and never claim the action happened (Task 3 test).
3. Wrong or missing API key in the n8n credential → the credential test fails with the API's 401 instead of saving a broken credential (Task 1 test via live n8n run in Task 4).
4. Agent down → the node errors visibly (n8n's red node), not an empty success (Task 4 manual check).
5. `docker compose up` without `AGENTES_API_KEY` → stops with a message naming the variable (Task 4 test: `docker compose config` in CI fails without it and passes with it).
